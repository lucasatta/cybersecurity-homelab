# Wireshark Traffic Analysis

## Objective
The objective of this lab is to observe and analyze network traffic generated between Kali Linux and Ubuntu Server using Wireshark.

## Capture Setup
Wireshark was used on the Kali Linux internal interface connected to the `cyberlab` network.

The main display filters used during the analysis were:

- `icmp`
- `http`
- `tcp.port == 80`
- `ip.addr == 10.10.10.20`
- `tcp.port == 22`

## ICMP Traffic
ICMP traffic was generated using `ping` between the two virtual machines.

By applying the `icmp` filter in Wireshark, I was able to observe ICMP Echo Request and Echo Reply packets exchanged between Kali Linux and Ubuntu Server.

This helped me understand how `ping` uses ICMP to verify host reachability

## HTTP Traffic
HTTP traffic was generated by accessing the Apache web server running on Ubuntu Server.

Using the `http` display filter, I observed HTTP requests and responses, including a `GET` request from Kali Linux and the corresponding response from the Ubuntu Server.

This helped me understand the basic request-response model used by HTTP.

## TCP Handshake
By filtering TCP traffic in Wireshark, I observed the 3-way handshake used to estabilish a TCP connection:

1. `SYN` - sent by the client to initiate the connection;
2. `SYN/ACK` - sent by the server to acknowledge the request and accept the connection;
3. `ACK` - sent by the client to complete the handshake.

This helped me understand how a TCP connection is established before application-layer data is exchanged.

## What I Learned
- How display filters help isolate relevant traffic;
- How ICMP Echo Request and Echo Reply work when using the `ping` command;
- The HTTP request-response model;
- The TCP 3-way handshake;
